## 0. 一页结论

| 问题 | 实测答案 |
|---|---|
| 抓取带能到多远？ | **含齿面中点补偿的完整抓取解算：r ≤ 0.30 为 100%**，r=0.31 → 60%，r=0.32 → 0%。现有 `GRASP_ZONE_RADIUS` 上限 0.28 **偏保守，可放宽到 0.30** |
| 手部占多大？ | 下探姿态（43mm 开度）世界水平外廓 **82.8 × 82.6 mm**（半宽 49mm）；闭合时也有 74.5mm 宽 |
| 容器壁能多高？ | 内腔半宽 50mm → 壁高 ≤ **62mm**（全轨迹口径）；半宽 55mm → ≤154mm（基本解放） |
| O4 缝能多窄？ | **≥ 83mm**（43mm 开度下的手部外廓，**且齿面中点偏心 48.9 / 33.9mm**，见 §2.1）；O4 取 **106mm**（已实测 12/12）；导墙（离目标 53mm）高 ≤ **45mm** |
| O3 能靠倾斜让开吗？ | 倾斜本身可行（±40° 全部 IK 可解），但**"低梁必须挡路"在 SO101 上不成立**：整条轨迹在近侧的最低点是 139mm，而就位时腕部在近侧是 177mm ⇒ **清得过梁的梁挡不住抓取，挡得住抓取的梁一定撞臂**。O3 需要换设计（见 §5） |
| O2 俯视遮挡能做吗？ | **不能**。69 个候选里只有 1 个不撞臂。俯视相机 + 竖直接近的组合下，"挡得住"和"进得去"是互斥的（见 §6） |
| 障碍物能放哪？ | 全轨迹 AABB 为 x∈[−64, 233]、y∈[−215, 278]、z∈[−2, 354] mm。**目标周围 50mm 以内是钳口走廊，不能放任何东西** |
| 现有布局随机化自洽吗？ | 是。200 组零兜底、零越界，最小两两间距 12.0mm、底座让开 120.0mm |

## 1. 测量口径（为什么这么量）

| 口径 | 理由 |
|---|---|
| 手部外廓用**网格顶点**而不是 body 包围盒 | 手由 11 个 STL 部件组成；包围盒会把指缝间隙也算成实体，缝宽会算小一半 |
| 顶点用"**每部件凸包 + 1500 点抽样**"（364310 → 100815） | 凸包顶点是原始点的子集，外轮廓精确；抽样保住凹处（指缝）。被丢掉的点只能在凸包内部 ⇒ **不会低估机械臂占的空间**（偏保守） |
| 竖直占用剖面 `H(A)` 用**环带** `A ≤ r ≤ A+10mm`，不用 `r ≥ A` | 墙是"半径 A 处的薄环"，不是"从 A 往外全都是墙"。用 `r ≥ A` 会把 200mm 外的底座算进来，整个剖面塌成 −2.4mm（已踩） |
| `H(A)` **分近侧/远侧** | 低梁在"朝底座"那一侧；整环最小值会把两侧混在一起，看不出倾斜到底把腕部挪到哪边 |
| 可达性分 **exact / position_only** | `auto_soft_axis` 会放弃最难的那个姿态分量去保住位置，把它算作成功会虚报包线 |
| 可达带要跑**整个专家轨迹**（含齿面补偿） | 齿面中点补偿会把 IK 目标从物体中心推开最多约 2cm；只测 TCP 可达性会高估（差 0.02~0.03m，见 §5） |
| 干涉判定用 **`Zmin(x, y)` 高度图** | 每个扫掠帧做一次散点最小值，之后任何障碍物（立板 / 吊板 / 环形墙）都只是查表，不必拿 10 万顶点反复重扫 |

## 2. 夹爪与手部

- 开度范围：**2.28 ~ 93.69 mm**（与 `env.py` 注释的 2~94mm 一致）
- 手部世界水平外廓（相对**齿面中点**，取 5 个 seed 的最大值）：

| 姿态（开度） | 闭合方向全宽 | 铰链方向全宽 | 半宽（闭合方向） |
|---|---|---|---|
| 完全闭合（2.3mm） | 74.5 mm | 75.3 mm | 42.8 mm |
| 握哑铃柄（16mm） | 74.5 mm | 75.3 mm | 37.7 mm |
| 握 35mm 方块 | 76.2 mm | 75.9 mm | 46.7 mm |
| **下探 35mm 方块（43mm）** | **82.8 mm** | **82.6 mm** | **48.9 mm** |
| 哑铃盘（44mm） | 83.8 mm | 83.6 mm | 49.4 mm |
| 全开（93.7mm） | 138.6 mm | 138.7 mm | 72.1 mm |

**两条推论**

1. **手指的占用半径到 48.9mm**。任何容器壁 / 导墙 / 遮挡板必须离目标中心 **≥ 50mm**，否则会与下探的钳口相撞。
2. 闭合时手也有 74.5mm 宽（颌体本身比开度大），所以"手能伸进去的最小缝"是 **83mm**（下探姿态），不是开度 43mm。

### 2.1 ⚠️ 这张表必须按"开度"读，而且外廓是**不对称**的

M2 做 O4 窄缝时在这里踩过一次，错了一个量级，所以单独写清楚：

- **`outer_half_span` 与 `span` 不是两倍关系**：下探姿态 `outer_half_span_closing = 48.9mm` 但 `span_closing = 82.8mm` ⇒ 齿面中点**偏心**，一侧突出 48.9mm、另一侧只有 33.9mm。按 `82.8/2 = 41.4mm` 去算缝宽会得到一个**会撞**的尺寸（当时写成"90mm 缝每侧 3.6mm"）。
- **缝宽/容器内腔的下限由较宽那一侧决定**，而且墙要离目标中心 ≥（较宽一侧 + 余量）。

**开度决定手宽**——脚本专家下探用的开度与 IK 的齿面中点假设必须一致，否则齿面中点会偏：

| 下探开度 | 闭合方向全宽 | 单侧最大突出 | 用途 |
|---|---|---|---|
| 43 mm（`width + 2×PAD_CLEARANCE`） | **82.8 mm** | **48.9 mm** | **IK 的齿面中点就是按这个开度算的** ⇒ 专家必须用这个开度下探；O4 的缝宽就是按它算的 |
| 57 mm（`width + JAW_CLEARANCE`，M0 时的现状） | **130.3 mm** | **66.0 mm** | 只适合 hover/传输段；用它下探会让手宽掉到 130mm 并**磨墙 −4.6mm** |
| 93.7 mm（全开） | 138.6 mm | 72.1 mm | 接近物体前的空档 |

**结论**：任何"能不能进去"的尺寸问题，都必须同时注明**开度**与**较宽一侧**；只看"全宽的一半"会错。

## 3. 可达带

| 口径 | 结果 |
|---|---|
| TCP 纯竖直可达（`soft_orientation` 严格成功，位置误差 <3mm） | r ≤ 0.33 仍 **100%**（个别半径 99%），几乎不构成约束 |
| **完整抓取解算**（齿面中点补偿 + hover/reach/grasp/lift 全路点，35mm 方块） | r ≤ 0.30 → **100%**；0.31 → **60%**；0.32 → **0%** |

**结论**：真正约束场景设计的是第二行。**现有 `GRASP_ZONE_RADIUS = (0.17, 0.28)` 可以放宽到 `(0.17, 0.30)`**，可用桌面面积增加约 15%，而且 0.30 以内仍是 100% 可解。

（本轮只测了 35mm 方块。杆和哑铃的齿面补偿更大 —— 哑铃握柄 16mm 时补偿反而不大，但**长物体的铰链对齐会额外吃掉可达性**，M0.1 要补齐 8 种物体。）

## 4. 竖直占用剖面 `H(A)`

`H(A)`＝"距目标中心水平距离 A 处，机械臂出现过的最低高度"。**墙高上限 = H(A)**。

| A (mm) | 抓取就位姿态 | **全轨迹**（含传输/抬升） |
|---|---|---|
| 20 | −3.1 | −0.9 |
| 25 | −2.3 | −0.6 |
| 30 | −1.5 | 0.2 |
| 35 | 24.6 | 4.4 |
| 40 | 39.4 | 21.3 |
| 45 | 52.5 | 50.4 |
| 50 | 153.7 | **61.7** |
| 55 | 154.5 | 153.6 |
| 60 | 155.0 | 157.1 |
| 65 | 156.7 | 158.6 |
| 70 | 156.7 | 158.6 |
| 75 | 157.0 | 158.9 |
| 80 | 72.4 | 26.6 |
| 85~95 | 26.6 ~ 16.2 | 23.9 ~ 16.2 |
| 100+ | −2.4 | −2.4 |

- A ≤ 45mm 的低值（甚至负值）**是手指本身**（静态摆位直接写 qpos，网格会轻微穿台）。这一段读数应读作"**此半径被手指占用，不能放东西**"。
- A ≥ 80mm 的低值来自**机械臂底座/本机**（目标距原点 0.17~0.28m，A=100mm 的环带已经够到 x≈0.12，即底座 keep-out 边界）。
- **真正可用的设计区间是 A ∈ [50, 75] mm**。

**由此得到的场景规格**

| 场景 | 规格 | 依据 |
|---|---|---|
| **P3 容器** | 内腔半宽 **≥ 55mm（内宽 ≥110mm）**，壁高 **≤ 50mm** | A=55 → H=154mm（解放）；留余量取 50mm 壁高，钳口与壁有 4mm 以上水平余量 |
| **O4 窄缝** | 缝宽 **106mm**，导墙高 **≤ 45mm**，墙离目标中心 **53mm** | 由 §2.1 修正后得到：106 = 2×(48.9 + 4mm)；A=45mm 处 H=50.4mm。**已实测 12/12、与墙零穿透** |
| **P4 堆叠 / O5 覆盖** | 覆盖块与目标同轴心、z 方向叠放；**不得在目标 50mm 内放额外的竖向障碍** | 钳口走廊半径 48.9mm |
| 干扰块（O2/P2） | 放在目标 **≥ 60mm** 以外，或放在工作区边缘 | 全轨迹 AABB（见 §7） |

## 5. 倾斜接近（O3 低梁）

在 (0.22, 0, 0.0175) 处、4 个颌滚转角上请求不同倾角（把 `Ry(π)` 换成 `Ry(π+tilt)`）：

| 请求倾角 | 实际达成 | 位置误差 | H(50) 整环 | **近侧（朝底座）@50mm** | **远侧 @50mm** |
|---|---|---|---|---|---|
| **0°** | 0.0° | ≤0.002mm | 177 mm | **177 mm** | 无material |
| +10° | 10.0° | ≤0.002mm | 65 | **187** | 65 |
| +20° | 20.0° | ≤0.002mm | 52 | **180** | 52 |
| +30° | 21.7°（到不了 30） | ≤0.002mm | 47 | **177** | 47 |
| +40° | 21.7°（同上） | ≤0.002mm | 47 | **177** | 47 |
| −10° | 10.0° | ≤0.002mm | 79 | 79 | 无 |
| −20° | 20.0° | ≤0.002mm | 61 | 61 | 无 |
| −30° | 30.0° | ≤0.002mm | 50 | 50 | 无 |
| −40° | 40.0° | ≤0.002mm | 39 | 39 | 无 |

**结论（和直觉相反，必须记下来）**

1. 倾斜 ±10~40° **全部 IK 可解**，位置误差 ≤0.002mm ⇒ **腕部姿态是 SO101 上真正可用的自由度**（+30°/+40° 只能达成 21.7°，是姿态极限）。
2. **正倾角把腕部甩到目标的远端（背离底座那一侧）**，近侧保持在 **≥177mm** ⇒ 腕部让开近侧的手段是正倾角。
3. **负倾角把腕部压低到近侧 39~79mm** ⇒ 负倾角只会让近侧更拥挤。

### 5.1 但是："低梁挡路"这个难度在 SO101 上不成立

把**整条专家轨迹**按侧拆开统计（`--only sweep`，5 seed × 130 帧）：

| A (mm) | 整环最低 | **近侧（朝底座）** | 远侧 |
|---|---|---|---|
| 45 | 50.4 | 54.7 | 50.4 |
| **50** | 61.7 | **139.1** | 61.7 |
| 55 | 153.6 | 153.6 | 242.9 |
| 60 | 157.1 | 157.1 | 245.2 |
| 65~70 | 158.6 | 158.6 | 261.7 |
| 75 | 158.9 | 158.9 | 不存在 |

对照 §5 表里"就位姿态下近侧的最低点 = **177mm**"：

- 一根放在近侧、离目标 50mm 的横梁，若**梁顶 ≤ 139mm** ⇒ 整条轨迹都不会碰它 —— 但就位时腕部在 177mm，**直接从梁上跨过去了，根本不构成阻挡**。
- 若**梁顶 > 139mm** ⇒ 它在传输/hover 阶段就会撞上（hover 路点把手的底部压到 139mm）。
- 想要它挡住"抓取"这个动作，梁顶必须到 **≥177mm** —— 那必然撞臂。

**两个区间不相交 ⇒ 无法用侧向横梁制造"必须重新定向腕部"的难度。**

**根因**（比结论本身更重要）：

> SO101 只能竖直抓取，于是它在目标周围的径向剖面是"**细柱子 + 远处的高台**"：
> **半径 <49mm 是手（一直到台面），半径 ≥50mm 之外只有 ≥139mm 的腕部/小臂**。
> 所以任何放在 r ≥ 50mm 处的竖向障碍，对"下探"这件事**几乎无关** ——
> 它只可能挡住传输，不可能挡住抓取。

**因此 O 族的难度必须建在"限制那只 83mm 宽的手能从哪里下去"上，而不是"在侧面挡一根梁"。** 可用的几何难度旋钮（都已被本轮数字支撑）：

| 替代 O3 | 做法 | 难度轴 | 用到的实测数字 |
|---|---|---|---|
| **O3′ 单向进给**（推荐） | 目标放进三面围栏，只留一个 **90mm 宽**的开口，墙高 **45mm**；钳口必须转到开口方位才进得去 | 方位 + 横向精度（5 自由度可靠 `shoulder_pan` 转过去，是可学的） | 手部外廓 82.8mm → 90mm 开口每侧余量 3.6mm；A=45mm 处 H=54.7mm |
| **O3″ 限高通道** | 目标在某块横板下方，板底 z 与 hover 路点冲突，逼专家降低 hover / 走更陡的下降 | 竖直裕度 | 需 M0.1 的 min/max 双网格才能定尺寸 |
| **O4 窄缝**（已有，可行，**已实测 12/12**） | 两堵导墙，缝宽 **106mm**、高 45mm、随目标一起转 | 毫米级横向精度 | 见 §2.1 与 §4 |
| **O5 覆盖堆叠**（可行） | 目标被另一块压住 | 长程 + 顺序 | 与 O3 无关，不受本条影响 |

> 这条结论同时解释了为什么 O4 可行而 O3 不可行：**O4 约束的正是那只手**（墙在 45~50mm、紧贴手的外廓），而 O3 想约束的是腕部，而腕部根本不在那儿。

## 6. 俯视相机遮挡（O2）—— **判定不可行**

全局相机在 `(0.17, 0, 0.66)` 正俯视（`fovy 46°`，`xyaxes="0 -1 0 1 0 0"`）。要让一块竖直立板挡住目标在图像里的一部分，板必须落在"相机轴 → 目标"这条近乎垂直的视线之间。

**需要的板高**（相对台面；5 个 seed、板距目标 d、三种遮挡率）：

| seed | d=30mm（25/50/65%） | d=60mm | d=100mm |
|---|---|---|---|
| 0 | 96 / 117 / 129 | 182 / 200 / 210 | 296 / 310 / 318 |
| 1 | 121 / 149 / 165 | 242 / 263 / 276 | 402 / 416 / 423 |
| 2 | 406 / 453 / 471 | — | — |
| 3 | 140 / 168 / 182 | 280 / 300 / 311 | 467 / 477 / 483 |
| 4 | 112 / 138 / 152 | 221 / 242 / 253 | 365 / 379 / 387 |

**与机械臂的干涉检查**：5 个 seed × 2 个方位侧 × 5 个距离 × 3 个遮挡率 = **69 个候选，只有 1 个通过**
（`y_side, d=60mm, 挡 25%, seed 0`，余量 −15.3mm，也就是刚好不撞）。其余全部干涉，最大余量 +472mm。

**根因**（这条要写进设计文档，避免以后重复试）：

- 相机在正上方 ⇒ 视线几乎垂直 ⇒ 板**贴近目标**才矮（d=30mm 需 ~96~140mm），**离远一寸就陡增**（每远 1mm 约多 2.75mm 板高）。
- 但贴近目标的那一圈（**≤48.9mm**）正是**钳口下探走廊**，板会直接撞上手指。
- 退到 50mm 以外，板的所需高度（≥160~200mm）又总是**高于机械臂在该半径的最低点**（62~240mm），而且差值随距离**扩大**（板高涨得比臂的净空快）⇒ **两个约束永远不相交**。

**替代方案（推荐第一个）**

| 方案 | 做法 | 代价 |
|---|---|---|
| **(a) 改遮腕部相机**（推荐） | 腕相机挂在 `gripper` 上、距 TCP 6cm、朝前下方；在目标**旁边**（≥52mm 外侧）放一道 30~50mm 高的矮墙或立牌，就能部分挡住腕部视野，而钳口从旁边照常下去 | 小；而且"自遮挡/贴近目标才看不清"正是真实水下作业的难点，叙事上也更对 |
| **(b) 把"看不清"交给成像轴** | O2 改成"目标弱纹理 / 与背景同色 / 低对比"，难度由水下档位（V1~V3）提供 | 零几何工程量，但"视觉遮挡"这个几何轴没了 |
| (c) 改全局相机（加俯仰/偏置） | 让立板能在低高度有效遮挡 | **会破坏与现有 320 条数据的一致性，需重采一份**，中期前不做 |

> 遮挡率本轮是**几何估算**（只对目标顶面 9×9 采样做射线求交）。选定方案后，M2 要用 `obstacle_grasp` 那套"藏板 / 藏目标"的像素差方法**实测复核**，并把实测值固化成自检项。

## 7. 专家轨迹扫掠包络

- 5 seed × 130 帧 = **650 帧**，全部成功求解（`seeds_solved = 5/5`）
- 全轨迹 AABB：**x ∈ [−64, 233] mm，y ∈ [−215, 278] mm，z ∈ [−2, 354] mm**

`y` 方向跨度到 ±215~278mm 说明：**机械臂在往返传输时横扫很宽**。所以干扰块/障碍物只有两个安全位置：

1. **贴着目标**（50~75mm 环带内、不落在钳口走廊方向上）——但那又要满足 §4 的高度上限；
2. **工作区边缘**（|y| 接近 0.28m 以上）——离目标远，干扰性弱。

这也解释了为什么"障碍物必须随目标一起随机化"：固定位置的障碍在 5 个随机布局里会时而干涉时而无关。

## 8. 布局与静置（复核）

| 检查 | 结果 |
|---|---|
| `layout.sample_layout` 200 组 | 兜底率 **0.0%**，最小两两间距 **12.0mm**（＝配置的 margin），底座最小让开 **120.0mm**（＝配置 keep-out），**越界 0** |
| 静置 20 seed × 250 步（0.5s） | 最大漂移 **0.019mm**，平均 0.001mm，最大倾角 **0.05°** |
| 漂移最大的物体 | `dumbbell_orange` 0.019mm、`dumbbell_purple` 0.016mm，其余为 0 |

**结论**：现有随机化与静置是自洽的，新场景沿用同一套参数即可，不需要重新标定。

## 10. 本轮的测量局限（设计时要留的余量）

| 局限 | 影响 | 处理 |
|---|---|---|
| 顶点用"凸包 + 抽样" | 凸包填掉凹陷 ⇒ 干涉判定**偏保守**（偏安全） | 可接受；若某级被判干涉而想抢救，再用全顶点复算一次 |
| 静态位姿直接写 `qpos`（无接触求解） | A<50mm 出现 −3mm 的穿台读数 | A<50mm 的读数只作"手指占用"的定性判断 |
| 遮挡率是几何估算（顶面 9×9 射线） | 与真实像素遮挡率有偏差 | M2 用像素差实测复核并固化 |
| 扫掠只覆盖 `cube_red`（35mm 方块） | 长物体（杆/哑铃）的齿面补偿与铰链对齐会**缩小**可达带 | M0.1 补齐 8 种物体 |
| 高度图只记 `Zmin` | 判定"中高度横梁"会保守（把只擦高处也算撞） | 对 O3 的结论**不影响**（结论来自"清得过 ⇒ 挡不住"的区间不相交，与保守方向无关）；若将来要做 O3″ 限高通道，需要 min/max 双网格 |
| 倾斜只测了 4 个颌滚转角 | 不是全姿态包线 | 需要时加密 |
